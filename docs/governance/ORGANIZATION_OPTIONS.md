# Future GitHub organization: investigation only

Status: **No organization created, repository transferred or privileges changed.** Investigated on 24 October 2026 using GitHub's [transfer documentation](https://docs.github.com/en/enterprise-cloud%40latest/repositories/creating-and-managing-repositories/transferring-a-repository) and [organization roles](https://docs.github.com/en/organizations/managing-user-access-to-your-organizations-repositories/repository-roles-for-an-organization).

The repository currently belongs to the personal account `thebookoftheway3`. Staying there has the lowest administrative overhead but leaves ownership, recovery and final authority concentrated in one account. Transferring to an appropriately governed organization could separate organization ownership, repository maintenance and security work. Creating an organization alone would not provide independent governance.

Before proposing a transfer, recruit willing independent maintainers and at least two trusted organization owners, record their responsibilities and conflicts, agree on succession and account recovery, establish a private security/conduct contact, and review costs and available protections. Use scoped teams with least privilege; sponsorship must not confer ownership or roadmap authority. Do not add names or grant roles until people accept.

GitHub requires permission to create repositories in the destination organization. Its default permissions apply after transfer; existing protections and integrations must be rechecked. Repository redirects do not redirect GitHub Pages, and creating a replacement at the old location can destroy redirects. Package associations can also need attention. These are migration checks, not evidence that this project currently uses Pages or packages. See the [transfer details](https://docs.github.com/en/enterprise-cloud%40latest/repositories/creating-and-managing-repositories/transferring-a-repository).

A future governance PR must compare staying under the current owner, transfer to a new organization and transfer to an existing suitably governed organization. Include public feedback, proposed membership/permissions, cost, conflicts, backups, history and attribution preservation, branch protections, CODEOWNERS, remotes/links, Actions, integrations, secrets, releases, rollback limitations and post-transfer verification. Require explicit owner authorization for execution. Decide separately whether to restrict repository transfer/deletion to organization owners using [organization policy](https://docs.github.com/en/organizations/managing-organization-settings/setting-permissions-for-deleting-or-transferring-repositories).

MIT reuse rights are unchanged by GitHub ownership. No legal entity, charitable status, trademark rights or guaranteed neutrality follows from an organization account. The goal is accountable stewardship and continuity, with public decisions and confidential handling of sensitive reports.
